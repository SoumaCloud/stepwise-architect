# Initial competition check

Checked 26 November 2026. This is a focused comparison of primary product sources, not an exhaustive market census or a completed customer-demand study. Funding was not verified. No claim that there are fewer than ten funded competitors or that this approach is unique is supported by this check.

| Alternative | Observed overlap | What Stepwise must prove |
| --- | --- | --- |
| [Superpowers](https://github.com/obra/superpowers) | Coding-agent skills and a development workflow across multiple clients | Contextual tool choices and outcomes add value beyond reusable workflow instructions |
| [BMAD Method](https://github.com/bmad-code-org/BMAD-METHOD) | Durable product and technical context, architecture, UX, implementation and founder guidance | Advice fits the exact workload and constraints, with traceable tool costs and switching trade-offs |
| [GSD Core](https://github.com/open-gsd/gsd-core) | Research, planning, execution, verification and persistent context across coding tools | Tool selection saves effort without requiring another heavy development process |
| [Infracost AI](https://www.infracost.io/product/ai) | Advertised AI spending scenarios, billing/usage reconciliation and developer/application attribution; early access | Useful advice at the current product-building step, including design/review/marketing tools outside AI usage billing |
| [CodeRabbit](https://www.coderabbit.ai/pricing) | Review automation, security and architecture-related review capabilities depending on plan | A lower-cost workflow meets the same actual review needs; avoid assuming a substitute is equivalent |
| Existing general coding assistants | Builders can already ask for research, tools, prompts and code changes | Persistent evidence, constraints and outcomes materially improve repeat use over an ordinary conversation |

GitHub API star counts on the check date: Superpowers 326,980; BMAD Method 55,770; GSD Core 11,853. Stars indicate attention, not funding, revenue or customer satisfaction. The older get-shit-done repository points to GSD Core as its active home.

The proposed advantage is a hypothesis: stay with an indie builder in the active project, remember accepted and rejected choices, check current evidence, prepare a useful next action, and measure total cost alongside quality. A catalog or visual graph alone will be easy to imitate. The initial alpha does not yet prove this advantage.

## Validate the pain

Recruit five builders who recently changed a tool or struggled with an unexpected AI/service bill. Ask about the last concrete decision, the alternatives they tried, time spent, what failed and the actual bill. Observe the present workflow before pitching the solution.

Search accessible public Reddit, Product Hunt, X, GitHub issues and specialist forums for recent examples. Record URL, date, user context and whether it is a customer experience or founder promotion. Deduplicate cross-posts, respect access restrictions and avoid interpreting a mention as willingness to pay. This repository prepares that workflow; it has not conducted interviews or completed a systematic community scan.

Test one narrow promise first: choose a suitable review, UI or agent workflow within the project's stated constraints and prove an improvement on the same task. Record rejected advice too. Let repeated use determine whether a daily update service or hosted dashboard is worth building.
